# External collection workspace

The source workspace keeps its two existing public references. A separately supplied private collection can use the same public adapter without copying assets into this package.

Extract an authorized collection next to the extracted `kdna-assets` source directory. The collection root owns its files and schema 2 `index/current.json`. From the source directory:

```sh
npm ci --offline --ignore-scripts --omit=optional --no-audit --no-fund
node scripts/audit-current.mjs --root ../official-current-collection --index ../official-current-collection/index/current.json
node scripts/audit-current.mjs --root ../official-current-collection --index ../official-current-collection/index/current.json --allow-read
```

The first audit denies disclosure by default. The second grants permission only for that local call and compares the observed public Read result with the indexed observation. The collection's own README supplies its actual catalog IDs and selection examples. An index is tied to the exact adapter binding hash; it must be regenerated by actual observations when that binding changes, rather than silently relabeled.

An optional collection revision map is supply metadata outside schema 2 and outside the KDNA protocol. It can retain a logical catalog ID while stating the original and current artifact paths, asset identities, versions and hashes. A newer asset is not a byte conversion of the original and does not inherit identity or Creation proof by naming convention. Keep original files and historical observations at their original meaning.

Only public Core interprets component content. All source/licensing and exact-file checks run before public admission and Read. Read-only use does not recreate a private Creation capability or establish human identity, legal clearance, usefulness, publication or permission to act. Separately supplied private material and acceptance records are not part of this public source bundle.
