# Changelog

## Unreleased

- Added a public-safe Creation acceptance fixture catalog with eight complete
  synthetic role paths and all thirteen hostile cases from the multi-role
  acceptance contract.
- Added a strict JSON Schema, cross-reference and authority invariants, and
  hostile mutation tests. Human and organization receipts are fixture-only
  `synthetic_fixture_authority` records and cannot evidence a real
  confirmation.
- Strengthened the existing forged-confirmation hostile case with correct
  current-digest subject-mismatch and missing-declared-authority probes. This
  exercises exact Engine binding and does not claim real-world identity
  authentication, which remains an external Host responsibility.
- Bound every synthetic source digest to the exact UTF-8 fixture material and
  added a hostile mutation test that rejects post-hash material changes.
- Bind each synthetic source that claims subject ownership to the exact
  represented subject ID, so the catalog exercises the same fail-closed
  source-grounding rule required by the Engine.
- Added a dynamically loaded adapter with no declared Studio Core package
  dependency. It auto-detects Studio Core or accepts an explicit path, executes
  all eight roles through the real Creation Engine readiness and compile
  operations, and evaluates all thirteen hostile mutations against Engine
  behavior.
- Added an explicit with-KDNA versus without-KDNA comparison fixture with
  identical task lanes, bounded improvement and exit expectations, real Engine
  execution, and current test-report acceptance binding. This remains a
  historical development-set contract and cannot close the current
  `APPLICATION_VERIFIED` gate.
- Added a separate technical-candidate runner whose current application gate
  measures exact-asset adoption fidelity on a fresh hidden free-response
  holdout. It uses no score or uplift threshold, requires stable declared
  direction plus zero critical/boundary violations, preserves failed attempts,
  and writes all run evidence only to an explicit private directory.
- Added an explicit optional independent Runtime matrix. It builds a fresh
  synthetic Agent-authored asset, verifies JavaScript Core validation,
  LoadPlan, and compact/full Capsules, then creates a temporary Swift Package
  to require the same LoadPlan and Capsule results from explicit Swift Core
  source. The matrix reports live source coordinates and artifact digest and
  always removes temporary files. It now compares complete compact/full
  semantic projections between JavaScript and Swift and persists an atomic
  machine-readable receipt. The same matrix now saves the accepted Engine
  workspace, invokes local Studio CLI `export-agent`, and binds its command
  result, build receipt, tool coordinates, and exact produced artifact.
  Clean-install behavior remains explicitly outside this source-candidate
  integration evidence.
- Kept static validation independent from Engine execution and kept `.kdna`
  export plus independent Runtime agreement outside the eight-role runner's
  claims; only the separate Runtime matrix may report its bounded agreement.
- Keep synthetic support and limit relations as creation evidence while
  checking only accepted priority and exception relations in Runtime
  projections.
- Made online Release verification read the canonical artifact and checksum
  URLs directly, with bounded retries only for network failures and transient
  HTTP statuses. Missing files, permanent HTTP failures, and digest mismatches
  remain fail-closed.
- Advanced the current validation and consumption baseline to the published
  `@aikdna/kdna-cli@0.35.1` release without changing either reference asset or
  its checksum. Historical rebuild receipts remain frozen at the exact
  toolchain that produced their evidence.
- Added a validation gate that requires every current index toolchain claim to
  match the repository's exact CLI dependency.
- Bound current-asset validation directly to the exact installed CLI package
  and current Node executable instead of delegating executable selection to
  `npx`.
